# Trellis

Локальное приложение для твоего Mac: деньги, смены, вес, замеры, питание и тренировки. TypeScript, React и PostgreSQL. Интерфейс открывается в браузере; записи хранятся в PostgreSQL на компьютере.

## Остаток и прогноз денег

В **Операциях** и **Аналитике** доходы, расходы и разница относятся к выбранному периоду. **Остаток по учёту** суммирует все записанные доходы и расходы по сегодня, включая предыдущие месяцы; операции с будущими датами пока не входят в остаток. Начальные деньги должны быть учтены в записях, чтобы сумма совпадала с реальными деньгами.

**Обязательства и прогноз** в Операциях всегда считаются от этого остатка на следующие 30 дней с учётом регулярных шаблонов. Выбор месяца, «Всё время» и поиск меняют статистику и список операций, но не остаток и прогноз. Учтённые платежи нужно отмечать через использование регулярного шаблона, чтобы его следующая дата сдвигалась и платёж не учитывался повторно.

## История действий

В **Данные → История действий** доступен журнал сохранённых изменений во всех разделах. PostgreSQL записывает создание, изменение и удаление каждой строки с полными состояниями до и после, временем действия, ключом записи и номером транзакции. Сюда входят выполнение и перенос задач, отметки привычек, повторения карточек, настройки, а также удаления связанных записей. Открытия разделов и запросы выгрузки JSON/TXT фиксируются отдельными действиями. Набор текста без сохранения, локальные черновики, поиск и отдельные клики не записываются.

При первом запуске обновлённой версии автоматически создаётся начальный снимок существующих записей. Его время означает включение журнала, а не создание старой записи. Удаления и изменения до этого момента неизвестны. Повторный запуск не дублирует снимок. История сохраняется независимо от текущих записей; обычное удаление, включая каскадное, её не очищает. Ошибка или откат транзакции отменяет и изменения, и запись в журнале. Журнал защищён от UPDATE/DELETE/TRUNCATE; API изменения или очистки истории нет.

**Скачать данные JSON** выгружает все разделы и полный `activity_log`, включая содержимое удалённых записей и вложения дневника. Формат резервной копии — версия 3; `activity_log_baselines` отмечает начало истории каждой таблицы, а `history` описывает значения действий и полей. Выгрузка выполняется в одной согласованной транзакции. История хранит полные версии, поэтому её размер увеличивается при изменениях больших заметок или вложений.

## Стирка и запасы

В **Стирке** добавляй вещи с описанием, фото и необязательным интервалом напоминания. **Постирал** позволяет выбрать сегодня или прошедшую дату; несколько выбранных вещей записываются одной транзакцией. Календарь показывает отметки по дням, история позволяет исправить дату/комментарий или удалить запись. Повторное сохранение одной вещи на ту же дату не создаёт вторую отметку. Напоминания видны внутри вкладки; уведомлений вне приложения нет. Само количество дней не означает, что вещь грязная. Если в базе остались таблицы стирок сентябрьской версии, они сохраняются и доступны в новой вкладке.

В **Запасах** добавляй редкие расходники: кофе, шампунь, гель для душа и т. п. **Купил** сохраняет дату, стоимость, упаковку и комментарий. Можно одновременно создать расход, привязать уже существующий расход или записать только историю. Один расход можно связать только с одной покупкой. Создание покупки/расхода и снятие отметки **Заканчивается** выполняются вместе; повторные нажатия блокируются во время сохранения.

Для созданного вместе с покупкой расхода редактирование покупки обновляет ту же операцию. У отдельно привязанного расхода сумма и дата берутся из «Операций»: изменения там сразу отражаются в «Запасах». Связанные расходы нельзя преобразовать в доход, пока существует связь с покупкой. При удалении денежной операции история покупки сохраняет её последние сумму и дату. Удаление покупки по умолчанию сохраняет расход; для созданного вместе расхода доступна отдельная кнопка **Удалить с расходом**. Удаление самого запаса сохраняет все денежные операции.

Заданный срок «обычно хватает на N дней» определяет примерную следующую покупку и ориентир накоплений на месяц (цена последней даты покупок × 30,4375 / N). Этот ориентир не вычитается из остатка и не добавляется в денежный прогноз автоматически. После трёх разных дат покупки предлагается средний интервал; он применяется только по твоему выбору, поскольку покупки про запас не отражают расходование. В список ближайших покупок входят заканчивающиеся запасы и ожидаемые покупки на следующие 30 дней. Все записи, изменения, удаления и открытия обеих вкладок входят в историю действий и JSON-выгрузку.

## Повторяющиеся события

В **Календаре → + Событие** выбери повторение: раз в N дней, по дням недели или рабочие/выходные. Для графика **2/2** выбери **Рабочие / выходные (2/2)**, оставь 2 рабочих и 2 выходных и укажи **первый рабочий день цикла**. Календарь покажет событие в рабочие дни автоматически, в том числе в будущих месяцах. При желании укажи последнюю дату повторения; она включается в график.

Редактирование и удаление применяются ко всей серии, включая прошедшие события. Время, место и заметки общие для серии. Настройки сохраняются в PostgreSQL и входят в JSON-резервную копию. Существующие разовые события сохраняются при автоматическом обновлении базы.

## Фото в дневнике

В разделе **Дневник** нажми **Добавить изображения** или вставь скопированную картинку через **⌘V / Ctrl+V** в поле записи. Можно прикрепить до 8 PNG, JPEG, WebP или GIF, удалить вложения при редактировании и сохранить запись только с картинками. Большие изображения уменьшаются до 2048 пикселей и сохраняются в WebP; при этом анимация GIF превращается в статичный кадр. Изображения хранятся вместе с записью в PostgreSQL и входят в JSON-резервную копию. Обновление базы выполняется автоматически при запуске.

## Выписка по операциям

В разделе **Операции** нажми **Скачать выписку**, выбери даты и нажми **Скачать TXT**. Изначально выбран месяц страницы; кнопка **Всё время** снимает обе границы. Даты включаются в период, поиск на странице не влияет на выписку.

В UTF-8 файле — доходы, расходы, разница, количество записей и все операции по порядку: дата, тип, сумма, название, категория, подкатегория, контрагент, комментарий, ID и накопленный итог периода. Итог показывает денежный поток, а не остаток на карте. Файл можно прикрепить к чату для сверки операций.

## Запуск приложения

1. Распакуй архив в отдельную папку. Старую папку проекта можно оставить.
2. Открой Postgres.app и запусти сервер кнопкой **Start**, если он остановлен.
3. Дважды нажми **Start.command** в новой папке. Либо открой терминал в этой папке и выполни:

```sh
npm start
```

При первом запуске зависимости установятся автоматически — нужен интернет. Версии зафиксированы. Затем приложение откроет браузер. При следующих запусках установка пропускается.

Нужен уже установленный Node.js 24 или новее. При запросе Postgres.app разреши локальное подключение Node/Terminal.

Работает один процесс: интерфейс и сервер запускаются вместе. Отдельные `npm run server` и `npm run dev` не нужны: обе команды теперь равнозначны `npm start`. Приложение ищет свободный порт, начиная с 5180. Повторный запуск из той же папки открывает уже работающий экземпляр. Адрес всегда напечатан в терминале. Остановка — **Control + C**.

По умолчанию используется прежняя база `life_dashboard`, пользователь — твоё имя в macOS, сервер — `127.0.0.1:5432`. Существующие операции и бюджеты сохраняются. Недостающие таблицы и колонки создаются автоматически. Если ранее ты менял подключение, перенеси соответствующие значения в `.env` по образцу `.env.example`.

## Что можно делать

- **Операции:** добавлять, редактировать, удалять доходы и расходы; создавать свои категории через «+» рядом с выбором категории; искать по названию, категории, месту и комментарию; смотреть месяц или всё время.
- **Быстрая запись:** на экране «Сегодня» одним действием добавить расход, задачу, описание еды без граммовки, запись сна или мысль в дневник.
- **План денег:** отметить запланированные смены и полученные выплаты, задать доступный остаток и траты; увидеть, хватает ли на ближайшую оплату квартиры и когда сценарий достигает цели подушки с покупкой и без неё.
- **Шаблоны операций:** добавлять частую покупку одним нажатием; хранить регулярные платежи с датой, заранее видеть обязательства, ближайший платёж и прогноз денежного потока; автоматически переносить платёж на следующий период после оплаты.
- **Аналитика:** расходы по дням, сравнение доходов и расходов за 12 месяцев, распределение по категориям, лимиты бюджета и превышения.
- **Смены:** учитывать оплату, дорогу, расходы, налог и статус выплаты; считать чистую ставку с дорогой; сравнивать варианты в симуляторе.
- **Вес:** записывать измерения, смотреть изменение веса и среднее по измерениям за 7 календарных дней.
- **Сон:** записывать точные дату и время засыпания и пробуждения, видеть длительность и среднее за последние 7 дней, оставлять комментарии и записи о сновидениях, редактировать историю.
- **Замеры:** хранить талию, грудь, бицепс и бедро; незаполненные значения остаются пустыми.
- **Питание:** выбирать продукт и массу, получать калории, БЖУ и клетчатку в порции и за день. Пищевую ценность можно уточнить в дополнительных полях.
- **Еда своими словами:** записывать приём пищи без граммовки. Такие записи хранятся в истории питания и не прибавляются к рассчитанным КБЖУ.
- **Продукты:** редактировать свой справочник значений на 100 г. Изменение продукта не переписывает ранее записанные приёмы пищи.
- **Тренировки:** записывать подходы через пробел, отдых и комментарий; сравнивать повторения по упражнению.
- **Данные:** выгрузить резервную копию записей и настроек в JSON.
- **Навигация:** менять порядок разделов перетаскиванием; список прокручивается отдельно и не обрезается на небольшом экране.
- **Цели:** большие цели с описанием, датой и следующим шагом; подцели на выбранный месяц привязаны к ним и видны в сводках «Сегодня» и «Обзор недели». Цели можно приостанавливать, завершать и возвращать в работу.
- **Календарь:** переносить задачи между днями мышкой. При удалении повторяющейся задачи выполненные экземпляры остаются в истории.
- **События:** отмечать встречи, клубы и концерты с временем, местом, подготовкой и заметкой после события.
- **Английский:** сохранять длительность разговоров, собеседника, новые фразы и заметки в разделе карточек; видеть прогресс к 20 разговорам от 20 минут.
- **Итог недели:** рядом с цифрами фиксировать, что получилось, что мешало и какой один шаг меняется на следующей неделе.
- **Трекер:** переименовывать действия рядом с их названием, не прокручивая таблицу до конца месяца.

В журналах кнопка **+** копирует запись на сегодня для быстрого повторения. У смен незаполненная дорога, расходы и налог означают неизвестные значения. Для расчёта чистой ставки заполни их; поставь 0, если затрат не было. Смены не добавляются автоматически в денежные операции, чтобы не учитывать доход дважды.

JSON-выгрузка содержит записи, шаблоны операций, настройки и бюджеты. Обратной загрузки JSON пока нет.

## Где менять код

| Файл                                                     | За что отвечает                          |
| -------------------------------------------------------- | ---------------------------------------- |
| `src/App.tsx`                                            | Боковое меню и переключение разделов     |
| `src/Operations.tsx`                                     | Форма и список денежных операций         |
| `src/Analytics.tsx`                                      | Графики денег и бюджет                   |
| `src/Journal.tsx`                                        | Формы журналов, расчёты и графики        |
| `shared/journals.ts`                                     | Поля и проверка данных каждого журнала   |
| `src/index.css`, `src/journals.css`, `src/analytics.css` | Цвета, размеры, расположение элементов   |
| `server/api.ts`                                          | API операций, журналов и выгрузки        |
| `server/database.ts`                                     | Подключение PostgreSQL и изменения схемы |
| `server/serve.ts`                                        | Единый сервер, выбор порта и браузер     |
| `scripts/start.mjs`                                      | Автоматическая установка и запуск        |

После изменения файлов интерфейса браузер обновляется автоматически. После изменения серверного кода останови приложение и снова выполни `npm start`.

## Проверка и сборка

После первого запуска доступны:

```sh
npm test
npm run build
```

В архиве также есть готовая сборка `dist`; её можно запустить командой `npm run preview`. Для обычной работы и изменения интерфейса используй `npm start`.

Проверены TypeScript, сборка, миграция старой схемы с сохранением записи, API, выгрузка данных и сохранение после перезапуска, занятый порт и повторный запуск. В Chromium проверены все разделы, графики и действия с записями. Автотесты используют изолированный PostgreSQL/WASM (PGlite); обычное приложение подключается через `pg` к установленному PostgreSQL. Запуск на macOS, Safari и с твоим экземпляром Postgres.app здесь не выполнялся.
